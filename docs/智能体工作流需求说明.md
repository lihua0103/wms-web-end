## 1. 背景与市场调研

### 1.1 调研背景

国际物流 / 仓储一体化平台正从"人操作系统"演进为"人机协作"：大模型智能体（AI Agent）通过自然语言理解业务意图，自主编排"查询 → 分析 → 决策 → 执行"的工作流。本次调研面向**开源生态 + 商业对标产品**，目标是确定 WMS 接入智能体工作流的产品形态与技术形态。

### 1.2 开源生态调研结论

| 层次 | 代表项目 | 与本系统的关系 |
| --- | --- | --- |
| 编排框架层 | LangGraph（ReAct / 状态图）、Dify、n8n、Flowise、Orkes Conductor（Netflix Conductor 开源版） | 后端 Agent 网关的可选执行引擎；前端不绑定任何一家，仅约定**协议契约**（SSE 事件流），保证后端可在 LangGraph / Dify / n8n 之间替换而前端零改动 |
| 领域工具层 | MCP（Model Context Protocol）服务器，如 FreightUtils MCP（HS 编码、UN/LOCODE、ADR 危险品、运费计算等中立校验层） | 智能体工具调用（Tool Call）的领域知识来源；国际物流场景（关务归类、运费试算、港口代码）依赖此类工具 |
| 商业对标 | project44 Supply Chain Autopilot（Agentic Workflow Manager）、Pando AI Agents（运力采购 / 调度 / 运费审核）、Wisor（货代报价与跟踪）、Splice（物流无代码工作流自动化）、Dynamics 365 Supply Chain Copilot | 确认产品形态：**Copilot 对话入口 + 可视化工作流管理 + 运行观测**三件套是行业共识 |
| 行业方法论 | ARC Advisory《Agentic AI Field Guide for COOs》：从**高频、低风险**的异常处置类工作流切入；DoorDash 多智能体协作生态 | 决定 P0 优先落地"异常预警处置 + 单据追踪"等低风险只读/半自动场景，写操作类工作流放 P1 |

**结论**：市场上不存在可直接引入的"国际物流智能体"开箱方案；主流做法是「编排引擎（LangGraph/Dify/n8n）+ MCP 领域工具 + 业务系统 Copilot 前端」。本系统采用同一形态：**前端提供 Copilot 对话入口与工作流管理界面，通过统一的 SSE 协议契约对接任意后端编排引擎；后端就绪前由前端内置本地预览引擎（Local Preview Engine）支撑演示与联调**。

## 2. 业务目标与用户角色

### 2.1 业务目标

1. **降本**：高频查询类工单（查库存、追单据）由智能体直接回答，减少人工翻页查询；
2. **提效**：异常事件（缺货预警、在途延误、单证缺失）由智能体主动发现、给出处置预案并一键生成工单；
3. **合规**：国际物流单证审核、HS 归类预校验引入 LLM 辅助，降低关务风险；
4. **可运营**：所有智能体工作流运行留痕（步骤、耗时、Token、结果），可观测、可审计、可回溯。

### 2.2 用户角色与核心诉求

| 角色 | 核心诉求 | 主要使用的功能 |
| --- | --- | --- |
| 仓库主管 | 总览异常、快速决策 | 顶栏智能体对话、找异常技能、运行记录 |
| 库管员 / 作业员 | 查库存、追单据进度 | 顶栏智能体对话（查库存 / 追单据技能） |
| 国际物流专员 | 运费试算、时效、关务合规 | 技能卡（运费 / 时效 / 关务）、单证审核工作流 |
| 财务 / 对账员 | 运费对账差异定位 | 运费对账工作流、运行记录详情 |
| 系统管理员 | 工作流启停、模型与触发配置 | 智能体中心 · 工作流管理 |

## 3. 总体架构

```
┌────────────────────────── WMS 前端（本仓库） ──────────────────────────┐
│  顶栏 Copilot 入口（lay-ai 抽屉）        智能体中心（/ai 菜单）          │
│  · 自然语言对话 · 技能卡 · 流式回复      · 工作流管理 · 运行记录          │
│  · 工具调用/步骤可视化 · 追问建议        · 详情时间线 · 失败重试          │
└───────────────┬────────────────────────────────┬──────────────────────┘
                │ REST（/wms/ai/**）              │ SSE（text/event-stream）
                ▼                                 ▼
┌────────────────────────── Agent 网关（后端，待建） ─────────────────────┐
│  会话管理 │ 意图路由 │ 工具注册表（WMS 业务工具 + MCP 领域工具）           │
│  编排执行（LangGraph / Dify / n8n 任选，可替换） │ 运行留痕与审计          │
└──────────────────────────────────────────────────────────────────────┘
                ▲ 后端未就绪时：前端「本地预览引擎」按同一 SSE 事件契约模拟
```

设计原则：

1. **协议优先**：前端只依赖 SSE 事件契约与 REST 契约，不感知后端编排引擎实现；
2. **降级可用**：`platform-config.json` 中 `AiEndpoint` 为空时自动切换本地预览引擎，演示 / 联调 / 生产三种形态共用同一前端代码；
3. **零新依赖**：SSE 用原生 `fetch + ReadableStream` 解析，不引入 eventsource / markdown 等第三方库（CONVENTIONS.md 约束）。

## 5. 接口契约

### 5.1 REST（前缀 `/wms/ai`，响应结构 `ApiResult<T>`）

| 端点 | 方法 | 说明 |
| --- | --- | --- |
| `/wms/ai/workflow/page` | GET | 工作流分页（keyword / scene / status / triggerType 过滤） |
| `/wms/ai/workflow/add` `update` `delete` | POST | 工作流 CRUD |
| `/wms/ai/workflow/toggle` | POST | `{id, enable}` 启停 |
| `/wms/ai/workflow/run` | POST | `{id}` 手动触发一次运行，返回运行记录 |
| `/wms/ai/run/page` | GET | 运行记录分页 |
| `/wms/ai/run/detail` | GET | `{id}` 返回含 `steps[]` 的详情 |
| `/wms/ai/run/retry` | POST | `{id}` 失败重试 |

### 5.2 SSE 会话协议（Copilot 抽屉）

请求：`POST {AiEndpoint}/v1/agent/chat`，`Accept: text/event-stream`，请求体：

```json
{ "sessionId": "sess-xxx", "scene": "wms", "messages": [{ "role": "user", "content": "查 WH001 库存" }] }
```

事件（`data:` 行携带 JSON，按序推送）：

| type | 载荷 | 说明 |
| --- | --- | --- |
| `thought` | `{text}` | 思考摘要（可折叠展示） |
| `tool_call` | `{id, name, args}` | 工具调用发起 |
| `tool_result` | `{id, name, summary, ms}` | 工具返回摘要与耗时 |
| `step` | `{key, title, status: running\|success\|failed}` | 工作流步骤状态推进 |
| `delta` | `{text}` | 正文增量（打字机） |
| `done` | `{usage: {tokens}, suggestions: []}` | 结束 + 追问建议 |
| `error` | `{message}` | 异常终止 |

本地预览引擎在前端按同一契约生成事件流（意图识别 → 模拟工具调用 → 模拟步骤推进 → 分块输出），保证三种形态（演示 / 联调 / 生产）交互一致。

### 5.3 平台配置（`public/platform-config.json`）

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `AiEnabled` | boolean | 智能体功能总开关 |
| `AiEndpoint` | string | Agent 网关地址；为空时前端使用本地预览引擎 |
| `AiModel` | string | 展示用默认模型名（实际路由由后端决定） |

## 6. 非功能需求

| 编号 | 需求 |
| --- | --- |
| NFR-1 | 性能：远端引擎首 token ≤ 2s（P95）；本地预览引擎首事件 ≤ 300ms |
| NFR-2 | 安全：SSE 请求携带现有认证 token；工具输出入前端前转义，杜绝 XSS；写类操作必须人工确认（P1 卡片式确认） |
| NFR-3 | 可观测：每次运行落库（步骤、耗时、Token、触发者），运行记录可追溯 180 天 |
| NFR-4 | 降级：`AiEndpoint` 为空 / 请求失败时自动回退本地预览引擎并明确标注"预览" |
| NFR-5 | 可扩展：后端编排引擎（LangGraph / Dify / n8n）可替换，前端零改动 |
| NFR-6 | 规范：全部遵循 `CONVENTIONS.md`（三件套结构、字典 tag、`message` 工具、不加依赖、主题变量取色） |

## 7. UI 需求要点

1. 顶栏胶囊 / 抽屉头部延续现有品牌渐变（`--el-color-primary` → `light-3`）；
2. 抽屉挂载 body，样式统一收敛在 `.ai-drawer` 全局作用域前缀下；
3. 智能体中心页面复用 `search-form + PureTableBar + pure-table` 标准三件套；
4. 状态 / 场景 / 节点类型一律走 `src/constants/wms.ts` 字典 `dictLabel/dictTag`，禁止页面写死颜色文案；
5. 运行详情时间线节点图标使用 `~icons/ep/*` 官方图标集。
