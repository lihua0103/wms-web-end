# 海关对接模块需求文档（关务协同）

> 版本：v1.0　日期：2026-09-27　模块代号：`customs`
> 本文档为「智联仓储 WMS」新增**海关对接模块**的需求与设计说明，页面三件套结构与后端接口约定遵循 `CONVENTIONS.md`、`docs/后端API对接指南.md`。

## 一、背景与调研结论

WMS 目前覆盖仓储作业全流程（入库/出库/库存/库内/运输/计费），但保税仓与跨境业务场景缺少与海关系统的申报对接能力。参考市面上专业系统的通行做法：

| 参考对象 | 借鉴点 |
|---|---|
| **海关金关二期**（保税物流管理系统） | 两仓货物进出库须报送**核注清单**（底账核增核减）、**核放单**（车辆进出卡口唯一单证），按**电子账册/料号底账**管理保税库存 |
| **国际贸易单一窗口** | 申报通道统一接入、回执状态管理、报文留痕可查 |
| **跨境电商通关服务平台**（进口统一版） | **三单对碰**：订单、支付单、物流单与清单比对，"清单核放、汇总申报"（1210 保税备货） |
| **专业保税仓 WMS 方案**（四方网络 4PNT、富勒 FLUX、点捷达等） | 关务系统 + WMS 双系统协同：WMS 产生业务数据 → 自动生成海关单证 → 申报 → 回执驱动库存核扣闭环 |

**结论**：海关对接模块应提供「账册底账 → 核注清单 → 核放单 → 三单对碰 → 报文回执」的完整单证链路，且与现有出入库单据建立关联。

## 二、业务流程

```
入库预约/出库单（保税业务）
   │ 自动生成
   ▼
核注清单 ──申报──► 海关审核 ──通过──► 底账核增/核扣（已核扣）
   │                   │退单
   ▼                   ▼
核放单（车辆/货物进出区卡口）   修改后重新申报
三单对碰（跨境电商）：订单 + 支付单 + 运单 ──推送──► 海关比对 ──► 对碰成功放行
所有申报/回执动作均产生报文日志（可查、失败可重发）
```

## 三、页面功能明细（5 页）

### 1. 账册管理 `/customs/ledger`（CustomsLedger）

海关电子账册/底账备案管理。

- 列表字段：账册编号、账册类型、企业名称、海关注册编码、监管方式、生效日期、失效日期、状态、备注
- 操作：新增/编辑/删除（表单弹窗）、**详情**（抽屉：账册信息 + 料号底账明细表：料号、物料编码、品名、单位、备案数量、已核扣、可用量）
- 搜索：账册编号、企业名称、账册类型、状态

### 2. 核注清单 `/customs/verify`（CustomsVerify）

保税核注清单（入区/出区申报单证），关联 WMS 出入库单。

- 列表字段：清单编号、类型（入区/出区）、监管方式、关联出入库单号、账册编号、申报数量（件数）、毛重、净重、状态、申报时间
- 状态机：`draft 草稿 → declared 已申报 → passed 审核通过 → deducted 已核扣`；退单 `refused`、作废 `cancelled`
- 操作：**申报**（草稿）、**同步回执**（已申报→审核通过→已核扣，模拟海关回执驱动）、**详情**（抽屉：单证信息 + 商品明细表：料号、商品编号 HS、品名、数量、单价、币制、毛净重）
- 搜索：清单编号、关联单号、类型、监管方式、状态

### 3. 核放单 `/customs/release`（CustomsRelease）

货物/车辆进出区卡口通行单证。

- 列表字段：核放单号、进出方向、车牌号、司机、关联核注清单、关联出入库单号、件数、毛重、状态、申报时间、放行时间
- 状态机：`draft 待申报 → declared 已申报 → released 已放行 → crossed 已过卡`；作废 `cancelled`
- 操作：**申报**（待申报）、**放行回执**（已申报）、**过卡确认**（已放行）、**作废**、**详情**抽屉
- 搜索：核放单号、车牌、方向、状态

### 4. 三单对碰 `/customs/triple`（CustomsTriple）

跨境电商三单（订单/支付单/运单）归集推送与对碰结果管理。

- 列表字段：单证编号、单证类型（订单/支付单/运单）、电商平台、关联订单号、外部单号（支付流水号/物流运单号）、金额、对碰状态、推送时间、对碰时间
- 状态机：`pending 待推送 → pushed 已推送 → matched 对碰成功`；`failed 对碰失败`（可重新推送）
- 操作：**推送/重新推送**、**详情**抽屉（含失败原因）
- 搜索：单证编号、平台、类型、状态

### 5. 海关报文 `/customs/msglog`（CustomsMsgLog）

与海关各通道收发的全部报文与回执留痕。

- 列表字段：报文编号、报文类型（核注清单/核放单/三单对碰/汇总申报/账册备案）、通道（单一窗口/金关二期/通关服务平台）、方向（上行/下行）、关联单证号、状态、重发次数、错误信息、时间
- 操作：**详情**（抽屉：请求/回执报文内容）、**重发**（失败报文）
- 搜索：报文编号、关联单证、类型、通道、状态

## 四、接口清单（前缀 `/wms/customs`）

| 实体 | 端点 |
|---|---|
| 账册 `/ledger` | 标准 CRUD |
| 核注清单 `/verifylist` | page/detail + POST `/declare` `{id}`、`/sync-receipt` `{id}` |
| 核放单 `/release` | page/detail + POST `/declare`、`/release`、`/cross`、`/cancel`（均 `{id}`） |
| 三单 `/tripledoc` | page/detail + POST `/push` `{id}` |
| 报文 `/msglog` | page/detail + POST `/resend` `{id}` |

字典枚举统一新增于 `src/constants/wms.ts`（海关对接段落），后端存储英文枚举 value。

## 五、非功能约束

- 页面遵循 pure-admin 三件套结构与 UI 设计规范（状态胶囊标签走字典、表格 minWidth、等宽数字）；
- 所有状态流转按钮按当前状态条件显示；
- 报文内容以 JSON 字符串存取，详情抽屉只读展示；
- mock 数据字段齐全、中文真实口径，供后端按同结构实现（切换后端前端零改动）。
